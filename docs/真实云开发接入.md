# 下一阶段：真实微信云开发

当前没有真实云函数和数据库实现，不存在可上线的后端。云端开发对话环境、GitHub代码存储和微信线上云环境是三件事。

## 用户准备

1. 在微信公众平台注册个人主体小程序，安装微信开发者工具，拿到AppID。
2. 根据实际会议协调功能核验个人主体可用类目，再按后台要求处理备案、认证、隐私说明等事项。不要为了通过审核选择不匹配类目。
3. 开通开发用微信云环境，核对费用、配额、地域和账号权限，提供非秘密的AppID/环境ID；扫码授权由本人完成。
4. 之后准备两个不同微信账号进行真实联调，再安排3—5人试用。账号、密码、验证码、AppSecret及证件不要发到聊天或提交Git。

## 后端实现要求

- 保持页面业务流程，替换 `lib/store.js` 为异步云端适配器，提供加载、保存失败、重试及刷新状态；mock与cloud必须明确开关，不静默降级。
- 服务端从云函数调用上下文取得可信身份，不能信任客户端actor/owner/OPENID。返回业务成员编号供辨认，不向普通成员暴露原始OPENID。
- 所有写操作和读取投影在服务端重新验证。数据库禁止客户端直接读写，凭有效邀请才允许匿名汇总/认领，成员才能读取具名信息。
- 邀请使用服务端密码学随机凭证，不沿用本地Math.random；失效/撤销策略与当前规则一致。
- 存储会议、角色绑定、回复、邀请及审计信息。认领唯一性须有事务或等效原子保障。
- 回复按用户独立存储，或在事务中读取并合并；不可由客户端覆盖整张会议表。
- 回复更新、角色迁移、锁定共享一致性机制：事务读会议版本、成员及回复，校验后原子提交；与改票冲突时重试或提示刷新。当前本地版本测试不等于已验证分布式事务。
- 头像主动上传云存储并约束权限，失败不能伪装成上传成功；不依赖本机临时文件路径。
- 新一轮创建在服务器验证发起人权限，关联旧会，重新认领/填写，不复制旧回复。
- 检查真实数据大小、并发/人数上限、计费和查询索引，避免不加限制的整库扫描或实时监听。

## 必须真实验证的场景

两账号独立登录并共享一场会议；两人同时提交不互相覆盖；重复认领抢占失败；伪造身份/越权读写被服务器拒绝；改票与锁定并发有一致结果；撤销凭证、截止、角色迁移、锁定后权限；存储与网络失败的错误提示。

完成这些证据后才能称M2真实联调通过。M1客户端测试不能替代上述验收。
