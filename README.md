# 多人会议时间协调 · 微信小程序

当前版本：**v0.3.0 · 2026-11-08 本机模拟测试版**。

本版以用户当天上传的 `Battle-for-A-MEETING--0.2.0.zip` 为核对基线：32个小程序文件与最终工作区逐字一致。已同步本轮157项测试和使用说明。上一版v0.2.0保留为历史快照。

[下载v0.3.0完整工程](https://github.com/ZamZheng/Battle-for-A-MEETING-/archive/refs/tags/v0.3.0.zip) · [本版检查与交接记录](docs/版本交接-2026-11-08.md)

**当前数据仅在本机保存。** 可在同一设备切换5个模拟身份测试流程；不同手机无法共同填写同一场会议。工程尚未接入真实微信登录、云数据库、服务端权限或消息推送。GitHub归档与微信端上传、真机/体验版验证是独立步骤。

## 打开工程

1. 下载ZIP并完整解压，在微信开发者工具选择“导入”。目录选包含 `project.config.json` 的根目录；源码位于 `miniprogram/`。
2. 保留用户已测试的AppID、项目设置和基础库 **3.17.5**。使用同一微信开发者账号继续；其他开发者使用自己有权限的AppID。
3. 点普通编译，进入 `pages/home/home`。无需安装npm依赖、构建npm或开通云开发。
4. 新解压工程不能恢复旧工程的本地会议、投票及头像文件。继续测试请保留原工程和缓存；不要将整个解压目录拖进旧的 `miniprogram`。

完整模拟操作见[导入与演示](docs/导入与演示.md)。

## 当前流程

- 首页邀请入口优先，发起会议其次，“我的会议”最后，清单约四条高度、内部滚动。本人创建的会议带蓝标；个人待补新增时段显示红标，正式补选后消失；发起人收齐全员回复后显示绿标，锁定后消失。
- 创建和编辑均逐行分栏填写成员称呼与备注，支持必到/可选、上移、下移、删除和添加。无需输入冒号、空格或换行分隔。备注仅在认领选项显示，其他位置用短称呼。
- 日期显示星期，时间滚轮分钟按10分钟选择，只有弹出滚轮文字为原字号1.5倍，页面日期/时间保留正常字号。创建错误弹OK、标红对应栏目并滚动定位。
- 独立身份页只选头像和角色，旁听在最后；未选头像弹窗提醒，取消或失败后清空无效选中。头像是用户主动选择的图片，不能证明真实微信身份。
- 逐候选选择可以/可协调/不行，显式提交后共享；已提交者默认只读、可主动修改。参与者提交后点OK回首页，高亮刚更新会议。
- 全部不行时先补提一个本人可以参加的未来时段。不同建议依次累加，相同时间合并，原回复保留，其他人只补未答新项；发起人可看待补短称呼。建议可以早于回复截止。
- 发起人在收集中可修改主题、目的和名单，预填独立页；角色ID保持稳定，删除已认领角色须确认转旁听。编辑期间新投票、新建议保留，不修改任何时间选项，也不通知成员。
- 任意“不行”使热力块优先红色，深浅按比例变化。建议来源标签关联原角色，显示称呼随该角色改名更正。
- 名单全员对所有当前候选完整提交（不含旁听）后，发起人从未来且无人选“不行”的时段中锁定，可以/可协调均接受，可选成员也不能有“不行”。收齐不等于必有可锁定时段。
- 最终安排可填网络会议链接（选填），点击“确认并复制会议通知”先保存再复制。通知顺序为主题、名单、时间、链接、查看最终安排，不含目的。

创建后先显示邀请卡，确认复制成功两秒后回首页。截止后禁改票，发起人可延长重开；锁定、取消、新一轮及版本校验仍保留。仅查看会议不能代替补选提交。

## 检查与范围

Node.js 22或以上版本（本次Node.js 24.22.1）执行：

```sh
npm run verify
```

不需要下载依赖。包含JS/JSON、5个页面、全局组件文件与事件检查，以及157项纯业务/模拟页面控制器测试，全部通过。用户在微信开发者工具中提供多轮操作截图与反馈；云端测试不渲染微信原生界面，尚无真实多人跨设备、真机和微信审核发布的验证结论。

`project.private.config.json`、Mac杂项和补丁ZIP不入库。ZIP保留代码和说明，不含wx本地缓存。生产共享数据接入方向见[真实云开发接入](docs/真实云开发接入.md)。
